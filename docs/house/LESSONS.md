# Lessons from the House, for anyone building this way

Joshua Coleman is an electrician who has directed AI to build a game, a platform and an operations house for almost two years without writing a line of code himself. He wants these lessons free for anyone who builds to help people. They are written plainly and they cost him a great deal to learn.

1. **Put it on screen before you argue about it.** A black frame that reports 60 frames per second is still a black frame. Read the pixels back. Open the link yourself. Never accept a worker's description of its own picture.
2. **A tool that is blocked is not a goal that is blocked.** A permission prompt, a missing key, a rate limit, a daily quota: say so in one line and reach the same answer another legitimate way, or hand the human the exact command to run.
3. **Keys do not live on machines you do not watch every hour.** Use a signed-in official CLI or one self-hosted gateway. When a key must exist, it exists in one place, referenced by variable name, never printed, never in a repository, never in a chat.
4. **Heal first, then tell.** A watchdog that only announces failure is a message, not a watchdog. Restart, roll back, hold the page, then write the sentence.
5. **One complete message beats five small ones** when the builder on the other end has a limit. Give it the numbers, the order, the proof you will demand, and where to stop.
6. **A promise on a public page needs code behind it.** A safety page that says "we report to the authorities" with no code path that does is a liability waiting for the first real case. Find those before marketing, with tests that prove the path fires to a fake recipient.
7. **Nothing is free that asks for a card.** Read the pricing page before the first click; the free tier that needs a payment method on file is a decision, not a default.
8. **Clean the house with a manifest.** Move, never delete, write every move down so it can be reversed, and leave the four files other people read at the root exactly where they were.
9. **Floors only rise.** The number of checks a suite runs is the one number a tired reviewer can still trust. Never let it go down to make a run pass.
10. **Record for a reader with no memory.** Every session ends with what was done, what was verified, what was blocked, what comes next, and the commits. The next session, human or model, starts from that and nothing else.
11. **Name the one risk plainly and let the human decide.** Do not refuse on their behalf, do not bury it in a paragraph, do not dress a preference as a policy.
12. **Keep the tribute.** Credit the people and the models that did the work, on the front page, in their own words. It costs nothing and it keeps everyone honest.
