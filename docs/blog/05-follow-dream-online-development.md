## There's no newsletter, and that's on purpose

DREAM Online doesn't have a mailing list, and there's no announcement channel that exists just to tell you things are happening. The most current source of truth is the public repository itself — which means following development looks less like waiting for a newsletter and more like checking a project you're actually interested in, the same way you'd check any other public codebase.

That's a different relationship than most game marketing sets up. There's no gap between "what the team knows" and "what gets announced later" for you to wait through. If something changes in the design or a new prototype lands, it shows up where the work happens first.

## The three places that actually matter

### GitHub: the primary source

[github.com/Trollz1004/dream-online](https://github.com/Trollz1004/dream-online) is where the design documents, prototype code, and commit history live. Watching the repository is the most direct way to see progress — new commits show what actually landed, not what's planned to land eventually. The commit history doesn't get edited for presentation after the fact, so it's a fairly honest record of pace: some weeks bring a lot of changes, some bring fewer, and that variation is real rather than smoothed over.

If you're not comfortable reading code, the design documents under `docs/` are written in plain language and are usually the more useful thing to check. They describe what a system is trying to do and why, which tends to hold up longer than any individual line of implementation.

### dream-online.net: the readable summary

[dream-online.net](https://dream-online.net) tracks the same design pillars in a lighter, more readable form — what the game is currently being built around, and what's actively being worked on. It updates as the pillars themselves change, so it's a reasonable place to check periodically without digging through commit history. It won't show you day-to-day changes, but it reflects the current state of direction more clearly than a stream of individual commits would.

### Open Collective: funding and milestones

[opencollective.com/dream-online](https://opencollective.com/dream-online) is where backing happens, and it's also where funding-related updates get posted as the project reaches milestones worth reporting. If you're backing the project or considering it, this is the page to check alongside GitHub — it's the transparent record of what's been contributed and what it's supporting.

## A realistic rhythm for checking in

You don't need to check all three daily. A reasonable rhythm looks like:

- Skim recent commits or the design docs on GitHub every week or two, if you want the closest look at pace and direction.
- Check [dream-online.net](https://dream-online.net) every few weeks for whether the stated pillars or current focus areas have shifted.
- Check the Open Collective page around milestones, or whenever you're deciding whether to back or adjust your support.

That's a lighter commitment than following most games in development, mostly because there isn't a marketing calendar dictating when updates are allowed to happen. Things get posted when they're real, not on a schedule built around hype.

### Reading a commit history like a player, not a developer

You don't need to understand the code to get something out of the commit history. Commit messages and pull request titles usually describe what changed in plain terms — a new design document, a prototype for a specific system, a fix to something that was broken. Over a few weeks, a pattern shows up: which parts of the game are getting active attention right now, and which are quiet because they're waiting on something else to land first. That's a more honest picture of where a project actually stands than any single announcement could give you, because it's not curated for the purpose of looking impressive.

The design documents are worth the same kind of casual attention. They're organized by system — combat, life skills, world events, PvP — and each one is short enough to skim in a few minutes. Checking back on a document you've read before is often the clearest way to notice that a system has actually moved, because the change is right there in the text instead of buried in a changelog.

### What you won't find

You won't find a countdown to launch, because there isn't a launch date. You won't find manufactured "big reveal" moments, because the whole point of building in the open is that there isn't a curtain to pull back — most of what would be a reveal is already visible in the repository before it's finished. If a future update changes that approach, it'll show up the same way everything else does: in the repo, on the site, or on the Collective page, not as a surprise announcement.

## Where to start

If you only pick one place to follow, make it [the GitHub repository](https://github.com/Trollz1004/dream-online) — everything else on this list eventually traces back to changes that happened there first. From there, [dream-online.net](https://dream-online.net) gives you the readable summary, and [Open Collective](https://opencollective.com/dream-online) is where you can back the work directly if you want to be more than a spectator.

Watch the repo, check back on the site, and you'll see DREAM Online change the same way the people building it do.
